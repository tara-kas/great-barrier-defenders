# Reef Rescue AUV: perception, telemetry and base-station planning

The lab now separates **Gemma visual perception**, **HTTP telemetry**, **Argon advisory reasoning**, **optional cuOpt candidate-route evaluation**, and the **local safety/controller loop**. Model and optimizer outages remain explicit. A configured endpoint is not proof of a deployed service, an on-robot runtime, or measured edge performance.

```text
Robot tool-camera JPEG ──► Gemma perception adapter ──► bounded observations
Local sonar/odometry ───────────────────────────────────────────┤
Known species/genet registry ── separate authoritative lookup ──┤
                                                             ▼
5 Hz local recorder ──► opt-in HTTP batches ──► base-station memory
                                                             │
                         optional cuOpt corridor costs ◄───────┤
                                                             ▼
                              Gemini 4 Argon / Interactions advice
                                                             │
                     local freshness, action and clearance verification
                                                             ▼
                          local controller / reflexes / mission outcome
```

Gemma estimates visible health; it does not infer lineage. Its numeric confidence is an **uncalibrated model score**, not measured classification accuracy. The perception prompt receives the image, active inspection target ID and phase; simulator health/genet truth is deliberately omitted. Unknown or failed perception cannot become an empty, safe seabed. Existing scripted synthetic sensing is labelled separately. The core motion/reflex implementation contains no network calls; a cloud plan cannot override local eligibility, freshness, route or outcome checks. Safety continuing during a remote outage is not equivalent to completing a mission without required perception.

## Runtime configuration

| Component | Environment | Actual scope |
| --- | --- | --- |
| Gemma | `GEMMA_BASE_URL` (OpenAI-compatible `/v1` base), `GEMMA_MODEL` (default `gemma-4-E4B-it`), optional `GEMMA_API_KEY` | POSTs real camera pixels to `/chat/completions`; model name must match the server's served name. |
| Gemma location | `GEMMA_DEPLOYMENT=robot`, `base_station`, `modal`, or default `unverified` | Declared deployment metadata only; hardware locality and latency must be measured. A Modal endpoint is remote, never onboard. |
| Argon | `GEMINI_API_KEY` or `GOOGLE_API_KEY`; optional `ARGON_MODEL` (default **`gemini-4-argon`**) | Actual Google Interactions call, low thinking, 512 output-token bound, 25-second request timeout. No fallback model. |
| cuOpt | `CUOPT_ADAPTER_URL` (complete custom gateway `/solve` URL), optional `CUOPT_API_KEY`, `CUOPT_DEPLOYMENT` | Explicit custom gateway contract described below; not a claim that NVIDIA's native HTTP API accepts this payload. |
| Worker deployment | `LAB_ARCHITECTURE_BASE_URL`, optional `LAB_ARCHITECTURE_TOKEN` | Fixed HTTPS authenticated gateway forwarding these architecture endpoints to the Python backend. Without it, the Worker returns unconfigured statuses. It does not host GPU models. |

Run the local gateway with `python3 scripts/run_lab.py`. HTTP is permitted only for loopback adapter URLs; remote adapters require HTTPS. Credentials come from environment/runtime secrets and are never returned to the browser. No `.env` files are read by this lab gateway. The earlier `/api/lab/decision` endpoint remains a **separate legacy Gemini supervisory path**, with its own configured model; it is not relabelled Gemma or Argon.

## Endpoints and provenance

`GET /api/lab/architecture` reports `components.gemma`, `components.argon`, and `components.cuopt`: `configured`, `status`, `model`, `provider`, `deployment`, and `role`. Status starts `unconfigured` or `unverified`; only a valid actual provider reply changes it to `verified_response`. Failure changes it to `error`. Verification here proves a returned response passed the contract, not correct perception, robot residency, or closed-loop performance. The response also reports `localSafety.networkRequired:false` and telemetry receipts.

`POST /api/lab/perception` accepts `{id, observation, image}`. The image uses the existing bounded tool-camera JPEG contract (512 KiB decoded, maximum 768 pixels per side). Observation supplies an active `inspect_recipient`/`inspect_donor` phase and target/donor IDs. Response:

```json
{"id":"frame-1","requestId":"frame-1","frameTime":12.5,"source":"gemma","provider":"vllm_openai_compatible","model":"gemma-4-E4B-it","deployment":"unverified","summary":"Actual provider text","uncertainty":"Actual provider text","observations":[{"id":"recipient-1","health":"unknown","confidence":0}],"confidenceMeaning":"uncalibrated_model_score"}
```

This is a **schema illustration**, not a saved inference result. Replies also contain measured request latency and the SHA-256/time/dimensions of the actual JPEG. Valid health values are `healthy`, `bleached_alive`, `dead`, `unknown`; only the requested visible target ID is accepted. Missing target observations, foreign IDs and invalid scores reject the response. No health or genet ground-truth labels are supplied to the classifier prompt.

`POST /api/lab/plan` accepts `{id, observation, allowedActions, perception?}`. `observation.time` (or `frameTime`) is required and checked **before** any paid request. Perception may be the raw Gemma packet or the engine's bounded onboard wrapper. The request preserves sonar/fusion source labels, registry facts and declared route alternatives. Argon returns `decision`, `reason` and optional `routeMode` restricted to declared `direct`/`clearance` alternatives. The gateway adds `requestId`, `frameTime`, `source:"argon"`, provider/model/deployment, token usage and actual latency. `optimizer.source:"not_configured"` explicitly marks absent cuOpt. Configured cuOpt failure stops that plan rather than relabelling a local path as GPU optimized. The engine must ingest/verify the plan before applying it; there is no arbitrary model-generated actuator command.

`POST /api/lab/telemetry` accepts `{streamId, sequence, frames}`: one to five actual recorder frames, at most one batch per second and 64 KiB total. The UI uses 1.1-second, non-overlapping sends. Receipt fields are `{streamId, sequence, acceptedFrames, totalFrames, lastFrameTime, retainedFrames}`. Duplicate/out-of-order sequences or simulation times are rejected; a reset starts a new stream ID. The server keeps a **300-frame volatile ring**, at most 16 stream cursors, receipt count and last-receipt age. There are no model calls, image bytes, credential fields or persistent logs in this path. Disconnect stops uploads. This is a functioning HTTP demo uplink, **not an acoustic network model**. It does not yet provide a database, multi-user telemetry broker or replay service.

## Integrated authenticated Modal deployment

`scripts/modal_lab_backend.py` defines one Modal application, `reef-rescue-lab`, with an authenticated CPU `gateway` and two private GPU classes. `GemmaRuntime` runs actual vLLM vision inference; `CuOptRuntime` runs the native NVIDIA solver. Private Modal RPC connects them to the same validated adapters used locally. Separate images avoid coupling vLLM and RAPIDS CUDA dependencies. This is remote perception, **not an onboard Gemma deployment**.

Deployment entrypoint: `modal deploy scripts/modal_lab_backend.py`. The gateway requires secret `reef-rescue-runtime` containing `GEMINI_API_KEY` and `LAB_GATEWAY_TOKEN`; the model runtime uses the existing `huggingface` secret, accepting `HF_TOKEN` or `HUGGING_FACE_HUB_TOKEN`. The account must have accepted the model license. The browser never receives these credentials. The Site Worker forwards requests with `Authorization: Bearer <LAB_ARCHITECTURE_TOKEN>`, which must equal the gateway token. Only the gateway exposes HTTPS; vLLM binds loopback and GPU methods use private RPC. No unauthenticated model or solver endpoint is exposed.

Defaults are official HF repository `google/gemma-4-E4B-it`, served name `gemma-4-E4B-it`, vLLM `0.21.0`, Transformers `5.10.1`, the llguidance structured-output backend, CUDA 12.9, Gemma GPU fallback order `L4,A10` and solver GPU `T4`. The native optimizer image requests `cuopt-cu12==26.10.*` from NVIDIA's package index. `GEMMA_HF_REPO`, `REEF_GEMMA_GPU` and `REEF_CUOPT_GPU` are deployment-time overrides. Model fit and latency require actual startup measurements; choosing an edge-sized model does not establish edge residency or performance. A persistent Modal volume caches downloaded model weights. Runtime images are isolated; no model response or image is persisted by this application. GPU containers scale down after 600 seconds idle, with at most one container per service.

`POST /api/lab/warmup {}` starts private GPU initialization asynchronously and returns HTTP 202 with `status:"warming"`. Poll `GET /api/lab/architecture`; component `readiness` is `not_started`, `warming`, `ready`, or `error`, alongside `ready` and the independent provider-response `status`. Gemma readiness verifies a loaded model server; cuOpt readiness executes a real small GPU solve. Argon readiness means credentials are configured; `status:"verified_response"` separately records an actual validated API response. `pipelineReady` means these service prerequisites are available, not proven perception accuracy. Readiness expires after four minutes without verification or successful use; another warmup safely rechecks it. Camera inference waits for readiness rather than holding an HTTP request through model download. Startup is bounded to 840 seconds and inference to 25 seconds.

The integrated gateway defaults `/plan` to `requireFullStack:true`. This requires a bounded Gemma packet and successful native cuOpt solve before Argon is called. Explicit partial demonstrations may set false. A configured solver failure never silently falls back. Local `/plan` defaults false for compatibility; full-stack mode must be requested explicitly there. The legacy Gemini endpoint is separate and is not hosted by the integrated Modal gateway.

`scripts/cuopt_route_adapter.py` converts each declared corridor into a bidirectional weighted waypoint graph, computes a GPU cost matrix with `WaypointMatrix`, and calls `routing.Solve`. It accepts only `SUCCESS`, zero infeasible orders, one vehicle, both required endpoints and a finite nonnegative objective. A timeout, partial route or malformed result is an error. It compares the actual solved objective across declared corridors. This is **weighted corridor evaluation**, not free-space path generation or hydrodynamic optimal control. Each directed edge costs estimated transit seconds at a nominal 0.6 m/s plus projected current, clamped to 0.15–2 m/s, plus a proximity penalty of 30 weighted seconds per metre inside a 1.2 m contact radius. At most 32 supplied fusion contacts contribute. These explicit engineering weights are uncalibrated; `costModel`, `inputContacts` and `inputCurrentVector` accompany the result. Dynamic collision avoidance, terrain clearance and feasibility remain local checks. The cost can favor a longer clearance corridor when synthetic contacts obstruct the direct corridor.

Custom optimizer request: `{id, alternatives:[{id,points}], fusion, currentVector}`. Successful response contains matching `id`/`requestId`, `source:"cuopt"`, `configured:true`, `status:"solved"`, `solverStatus:"SUCCESS"`, `routeMode`, `objectiveCost`, `costs`, `solveTimeMs`, `model` and `solverVersion`. Argon's structured response is constrained to this route; a different or missing route rejects the plan. Native NVIDIA HTTP APIs have different schemas; external `CUOPT_ADAPTER_URL` must refer to this adapter. The standalone adapter requires `CUOPT_API_KEY` and binds loopback port 8091.

Perception now supports `inspect_fragment`: the provider must return `fragmentVisible`, `gripperState` (`empty`, `holding`, `unknown`) and an empty health-observations array. Colony inspections still require one bounded target-health result. Send the engine's `observation.perceptionRequest` with stable capture ID, target ID/kind and minimum simulation time. HTTP request IDs are unique per retry; the response retains both `requestId` and stable `captureRequestId`, plus target provenance and the actual image hash/time. The engine independently verifies camera acquisition time, target association, freshness and local safety. The prompt excludes registry truth, including any expected-health value in the engine's capture record.

## Read-only team mission evidence

The lab can display the canonical team's Mission Control output without importing its control loop. Start `python3 scripts/run_lab.py --team-run-dir /absolute/path/to/run`, or set server-only `TEAM_RUN_DIR`. The bridge reads only fixed files in that directory: `registry.json`, `decisions.jsonl`, and `frame.png` (or `frame.jpg`/`frame.jpeg`). No demo directory or sample frame is selected by default. The actual unchanged `dashboard.server.read_registry` and `read_decisions` functions parse bounded in-memory snapshots; the bridge never writes these files or sends robot commands.

`GET /api/lab/team-state` returns the canonical `mode`, `registry`, `detections`, `decisions`, update timestamps and `frame_synthetic`, plus `configured`, `status`, `stale`, `provenance` and a same-origin `frameUrl`. `GET /api/lab/team-frame?v=<mtime>` serves the bounded actual PNG/JPEG. The only query parameter allowed is a numeric frame version; clients cannot choose source paths. Symlink escapes, oversized files, malformed JSON, nonfinite records and changing reads are rejected. Registry/decision sources are limited to 2 MiB each, frames to 2 MiB, state JSON to 1 MiB, returned registry entries to 1,000, detections to 256 and latest decisions to 200, with original counts reported.

Optional `source.json` contains `{"frameSynthetic":true}` for a rendered/mock frame, or false for an operator-declared camera source. Missing metadata remains **unknown**, not silently real or synthetic; `frameOriginVerified:false` explicitly distinguishes declarations from verification. The bridge does not infer provenance from coral appearance. A source older than 30 seconds is labelled stale. A missing or corrupt frame leaves registry and decisions available with `frameUrl:null` and an explicit `frameWarning`; no replacement frame is generated. On a read error, HTTP 503 preserves the last good payload with `ok:false`, `status:"error"` and a sanitized message; the UI retains its last good view. No configured directory produces explicit unconfigured state with empty arrays and no frame.

The Modal gateway includes the same authenticated read endpoints and canonical parser, but reports unconfigured unless a real `TEAM_RUN_DIR` is mounted/configured. The app does not automatically upload local artifacts, mount a team run volume, or label browser simulation state as team mission output. Deploying this addition can restart the GPU app; coordinate deployment around live inference.

## Verification and remaining deployment work

On November 8, 2026, the primary agent completed an **actual Argon planning-stage call** with a seed-42 engine approval observation at simulation time 21.4 s: approximately 26.6 KiB of synthetic sonar/UV/registry telemetry, no Gemma result and no camera image. The call returned `proceed` with the declared `clearance` route in **16,693 ms**. Its reason explicitly acknowledged the missing camera. No interaction ID was present in that provider response; the gateway preserves null rather than inventing one. cuOpt was explicitly unconfigured. This verifies the Argon transport/planning stage only, **not** the complete Gemma → telemetry → Argon → cuOpt closed loop or onboard perception.

The integrated Modal deployment subsequently loaded the actual Gemma4 E4B checkpoint (14.89 GiB on disk, 15.18 GiB reported model allocation) on an NVIDIA A10. Native cuOpt warmup completed an actual GPU solve. The primary agent's first rendered recipient camera request returned a valid Gemma observation in **15,144 ms**: `unknown` with score `0`, describing a white/light-purple rough coral/clump. The engine correctly held the uncertainty gate. This verifies real camera transport and model inference, not successful health classification or a completed mission. The adapter now requests `enable_thinking:false` and temperature zero for bounded visual classification; registry truth remains excluded from the classifier input.

Tests exercise actual request construction and strict failure handling using mocked Gemma/cuOpt/provider transports, plus real loopback HTTP. A model mock is test evidence, not a live-model demonstration. GPU deployment and runtime verification are performed by the primary agent/account owner separately from these contract tests. Required acceptance checks remain: actual model startup and image inference, positive/negative camera controls, native GPU solver smoke test, a complete closed-loop episode, measured latency, and link-loss safety. A successful build alone is not a successful live pipeline.
