# Reef Rescue AUV: perception, telemetry and base-station planning

The deployed browser mission uses **Gemma visual appearance**, **HTTP telemetry**, an **inspectable local decision policy**, **native cuOpt corridor evaluation**, and the **local safety/controller loop**. **Argon supplies bounded advice for held mission issues and reviews completed episodes.** Its assistance can recommend rescan, hold or abort; it cannot authorize handling or replace the local planner. Model and optimizer outages remain explicit. A configured endpoint does not establish on-robot residency or correct perception.

Production autonomous missions are **model-guided only**. There is no presentation-only start, scripted mission bypass or partial-stack UI path. Missing/invalid/stale responses lead to hold, fresh rescan or abort. Manual Pilot and operator fault injection remain explicitly human actions; they do not replace model authorization or establish autonomous completion.

```text
Browser tool-camera JPEG ──► Gemma appearance/v1 ──► fresh target evidence
Synthetic sonar/odometry ────────────────────────────────────┤
Known registry eligibility/genet ── independent lookup ──────┤
                                                           ▼
5 Hz recorder ──► HTTP batches ──► base-station volatile memory
                                                           │
                              native cuOpt corridor costs ◄─┤
                                                           ▼
                           inspectable local policy /plan
                                                           │
                         local freshness/eligibility/clearance checks
                                                           ▼
                         loose-fragment pickup and verified placement
                                                           │
                         held issue ──► Argon /assist: rescan / hold / abort
                         completed/aborted episode ──► optional Argon /review
                                                       advice only, no control

Independent Isaac RTX runtime ──► authenticated snapshot relay
                                  └─► read-only Mission evidence view
```

Gemma describes visible object geometry and appearance; **it does not establish living tissue, viability, health, genotype or treatment success**. Its confidence is an uncalibrated identification/appearance score, not measured classification accuracy. The model receives the image and a visual-task prompt, without target IDs, phase, expected-health labels or registry truth. The adapter attaches the requested target identity after validating the reply. Identity association is therefore a capture contract, not proof the model localized the correct object.

The browser mission uses already detached, scenario-permitted loose stock. Proceed requires fresh colony appearance evidence, an actual fragment view with the expected gripper state, and independent registered eligibility/species/genet agreement. It does not authorize cutting attached healthy coral. Unknown appearance, stale evidence or mismatched targets hold the mission or exhaust a bounded retry budget into abort. `health:"unknown"` in the new visual contract is intentional; it is not a failed appearance classification. Legacy health-only unknown responses never gain the new appearance authorization.

The core reflex loop contains no network calls. Local contact, clearance, conservation and outcome checks remain authoritative; a gateway proposal cannot override them. The default deployed Gemma and cuOpt runtimes are remote Modal services, so completing a model-guided mission still depends on their availability. The browser world and independent Isaac world are separate simulations, not synchronized physical twins.

## Runtime configuration

| Component | Environment | Actual scope |
| --- | --- | --- |
| Gemma | `GEMMA_BASE_URL` (OpenAI-compatible `/v1` base), `GEMMA_MODEL` (default `gemma-4-E4B-it`), optional `GEMMA_API_KEY` | POSTs real camera pixels to `/chat/completions`; model name must match the server's served name. |
| Gemma location | `GEMMA_DEPLOYMENT=robot`, `base_station`, `modal`, or default `unverified` | Declared deployment metadata only; hardware locality and latency must be measured. A Modal endpoint is remote, never onboard. |
| Argon | `GEMINI_API_KEY` or `GOOGLE_API_KEY`; optional `ARGON_MODEL` (default **`gemini-4-argon`**) | Held-issue assistance (512 output tokens) and terminal review (768), using Google Interactions, low thinking and a 25-second socket timeout. Never called by mission `/plan`. |
| cuOpt | `CUOPT_ADAPTER_URL` (complete custom gateway `/solve` URL), optional `CUOPT_API_KEY`, `CUOPT_DEPLOYMENT` | Explicit custom gateway contract described below; not a claim that NVIDIA's native HTTP API accepts this payload. |
| Worker deployment | `LAB_ARCHITECTURE_BASE_URL`, optional `LAB_ARCHITECTURE_TOKEN` | Fixed HTTPS authenticated gateway forwarding these architecture endpoints to the Python backend. Without it, the Worker returns unconfigured statuses. It does not host GPU models. |

Run the local gateway with `python3 scripts/run_lab.py`. HTTP is permitted only for loopback adapter URLs; remote adapters require HTTPS. Credentials come from environment/runtime secrets and are never returned to the browser. No `.env` files are read by this lab gateway. The earlier `/api/lab/decision` endpoint remains a **separate legacy Gemini supervisory path**, with its own configured model; it is not relabelled Gemma or Argon.

## Endpoints and provenance

`GET /api/lab/architecture` reports `components.gemma`, `components.argon`, and `components.cuopt`: `configured`, `status`, `model`, `provider`, `deployment`, and `role`. Status starts `unconfigured` or `unverified`; only a valid actual provider reply changes it to `verified_response`. Failure changes it to `error`. Verification here proves a returned response passed the contract, not correct perception, robot residency, or closed-loop performance. The response also reports `localSafety.networkRequired:false` and telemetry receipts.

`POST /api/lab/perception` accepts `{id, observation, image}`. JPEG input is bounded to 512 KiB decoded and 768 pixels per side. Observation carries the current `inspect_recipient`, `inspect_donor` or `inspect_fragment` capture request, target ID/kind and minimum simulation time. HTTP IDs are unique per attempt; `captureRequestId` remains stable across retries for the same requested view. A schema illustration, **not a recorded result**:

```json
{"requestId":"frame-1","captureRequestId":"capture-1","frameTime":12.5,"targetId":"recipient-1","targetKind":"colony","source":"gemma","visualContract":"appearance/v1","viabilityKnown":false,"targetVisible":true,"objectKind":"coral_colony","appearance":"pale_or_bleached","confidence":0.8,"fragmentVisible":false,"gripperState":"empty","observations":[{"id":"recipient-1","health":"unknown","confidence":0.8,"targetVisible":true,"objectKind":"coral_colony","appearance":"pale_or_bleached","viabilityKnown":false}]}
```

`objectKind` is `coral_colony`, `coral_fragment`, `other` or `unknown`; `appearance` is `pigmented`, `pale_or_bleached`, `bare_skeleton_or_algae` or `unknown`. Fragment requests return an empty colony-observations array and their visual fields at top level. Responses preserve actual provider/model/deployment, summary, uncertainty, measured latency and JPEG SHA-256/time/dimensions. The model uses temperature zero, thinking disabled, 384 output tokens and constrained JSON with an empty whitespace pattern. Incomplete or malformed output is rejected. This decoding constraint fixes observed whitespace-filled truncation without inventing observations. Legacy health-response compatibility is retained but never relabelled `appearance/v1`.

Optional `observation.imageFocus` guides the visual prompt without modifying the strict four-field JPEG object:

```json
{"source":"tracked_camera_projection","target":[0.42,0.81],"gripper":[0.51,0.33]}
```

At least one of `target` or `gripper` is required when imageFocus is present. Each supplied point is exactly two finite numbers in [0,1], with top-left origin; unknown fields, null points and alternate source labels are rejected. The renderer projects known tracked positions through the actual capture camera, and the gateway supplies those normalized coordinates and pixel equivalents to Gemma. **These points are not detector localizations, bounding boxes, proof of visibility or correct object identity.** No expected object kind, health, genet or target ID is added to the model prompt. Out-of-view points are omitted. The response retains the validated object as `inputImageFocus`, alongside the original image hash/time. Gemma must inspect the indicated pixels instead of a larger background colony; visible empty jaws, a piece between the pads and obscured/ambiguous jaws remain distinct outcomes. The complete `appearance/v1` and local safety gates still apply.

`POST /api/lab/plan` accepts `{id, observation, allowedActions, perception?, requireFullStack?}`. Finite simulation time is validated before solver work. The gateway runs native cuOpt on the declared corridors when configured, then calls the inspectable `local_mission_decision` function; **it does not call Argon or any language model**. Responses contain `source:"local_planner"`, `provider:"inspectable_policy"`, `model:"reef-local-policy-v1"`, `cloudReasoningUsed:false`, bounded `decision`/`reason`, request/time provenance, the solver-selected `routeMode`, and optimizer evidence. `latencyMs` measures elapsed adapter planning time including the configured cuOpt call; it excludes external HTTP transport and queueing.

Initial proceed requires the registered eligible pair, fresh ≥0.70 colony appearance scores (pigmented source and pale/bleached recipient), a fresh visibly identified pigmented loose fragment with empty gripper, and stock state `available`, `detachedAtStart:true`, `source:"scenario_permitted_loose_stock"` in `restorationMode:"loose_fragment"`. Retry requires remaining budget and fresh uncertainty or matching recovery-fragment evidence; otherwise the policy aborts. Confidence thresholds are engineering gates, not validated biological probabilities. The engine separately verifies the proposed action and route before application. Configured solver failure stops the plan; absent cuOpt is explicitly `optimizer.source:"not_configured"` and is incompatible with full-stack mode.

`POST /api/lab/assist` accepts an explicit held/paused issue and current structured evidence:

```json
{"id":"issue-1","episodeId":"episode-uuid","issue":{"kind":"perception_uncertainty","reason":"Gripper gap remains unclear"},"observation":{"phase":"inspect_fragment","time":12.5,"held":true},"perception":{"source":"gemma","gripperState":"unknown"}}
```

`perception` is optional; when supplied it must be an explicit Gemma packet. `observation` must contain a short nonterminal phase, finite nonnegative `time`, and `held:true` or `paused:true`; completed/aborted episodes use `/review`. `issue.kind` is a short lowercase snake-case category and `reason` is 1–1,200 characters. Request/episode IDs are 1–160 characters from letters, digits, underscore, dot, colon and hyphen. Combined structured input is limited to 32 KiB. Argon receives structured evidence only, not a JPEG, through this endpoint.

A validated response contains `{id, requestId, episodeId, source:"argon_assist", provider:"google_interactions", model, action, reason, latencyMs, interactionId, advisoryOnly:true, controlAuthority:false, attempt, remainingAttempts, budgetScope:"gateway_process"}`. `action` is strictly `rescan`, `hold` or `abort`; `proceed`, actuator coordinates, code changes and gate overrides are not supported. Actual provider latency and any returned interaction ID are retained; a missing ID remains null. Advice is applied through the engine's checked rescan/hold/abort operations, never directly to actuators. An issue such as uncertain camera evidence or a dropped fragment does not authorize recovery motion without a fresh matching inspection.

The gateway permits **three provider attempts per stable episode ID**, including failed provider calls. Duplicate request IDs within that episode are rejected. Up to 64 episode budgets remain in volatile process memory; reaching capacity rejects new episodes rather than evicting old limits. A real mission reset starts a new episode ID; reconnects and retries must retain it. Gateway restart/redeployment clears these budgets, so this is a process-scoped demonstration limit, not a durable account quota or protection against clients inventing episode IDs. Shared single-request concurrency and a one-second minimum interval per operation also apply. Input/duplicate failures return 400, rate/budget/capacity failures 429, missing Argon configuration 503, and sanitized provider/validation failures 502. The mission remains held on failure. Assistance does not require ready GPU services; `pipelineReady` still depends only on Gemma and cuOpt. Argon's health role is `uncertainty_assistance_and_between_mission_review`.

`POST /api/lab/review` accepts `{id, episode, transportActivity}` only when `episode.phase` is `complete` or `aborted`. At most 40 activity entries and the shared 32 KiB structured-input limit apply. It calls Argon with bounded finished-episode evidence and returns `{id, source:"argon_review", model, summary, recommendations, latencyMs, reviewOnly:true, controlAuthority:false}`. Recommendations are advisory text, never commands, patches or executable policy. The UI requests review explicitly between runs; review availability does not gate mission readiness. Missing credentials return 503 without modifying mission state.

`POST /api/lab/telemetry` accepts `{streamId, sequence, frames}`: one to five actual recorder frames, at most one batch per second and 64 KiB total. The UI uses 1.1-second, non-overlapping sends. Receipt fields are `{streamId, sequence, acceptedFrames, totalFrames, lastFrameTime, retainedFrames}`. Duplicate/out-of-order sequences or simulation times are rejected; a reset starts a new stream ID. The server keeps a **300-frame volatile ring**, at most 16 stream cursors, receipt count and last-receipt age. There are no model calls, image bytes, credential fields or persistent logs in this path. Disconnect stops uploads. This is a functioning HTTP demo uplink, **not an acoustic network model**. It does not yet provide a database, multi-user telemetry broker or replay service.

## Integrated authenticated Modal deployment

`scripts/modal_lab_backend.py` defines one Modal application, `reef-rescue-lab`, with an authenticated CPU `gateway` and two private GPU classes. `GemmaRuntime` runs actual vLLM vision inference; `CuOptRuntime` runs the native NVIDIA solver. Private Modal RPC connects them to the same validated adapters used locally. Separate images avoid coupling vLLM and RAPIDS CUDA dependencies. This is remote perception, **not an onboard Gemma deployment**.

Deployment entrypoint: `modal deploy scripts/modal_lab_backend.py`. The gateway requires secret `reef-rescue-runtime` containing `GEMINI_API_KEY` and `LAB_GATEWAY_TOKEN`; the model runtime uses the existing `huggingface` secret, accepting `HF_TOKEN` or `HUGGING_FACE_HUB_TOKEN`. The account must have accepted the model license. The browser never receives these credentials. The Site Worker forwards requests with `Authorization: Bearer <LAB_ARCHITECTURE_TOKEN>`, which must equal the gateway token. Only the gateway exposes HTTPS; vLLM binds loopback and GPU methods use private RPC. No unauthenticated model or solver endpoint is exposed.

Defaults are official HF repository `google/gemma-4-E4B-it`, served name `gemma-4-E4B-it`, vLLM `0.21.0`, Transformers `5.10.1`, the llguidance structured-output backend, CUDA 12.9, Gemma GPU fallback order `L4,A10` and solver GPU `T4`. The native optimizer image requests `cuopt-cu12==26.10.*` from NVIDIA's package index. `GEMMA_HF_REPO`, `REEF_GEMMA_GPU` and `REEF_CUOPT_GPU` are deployment-time overrides. Model fit and latency require actual startup measurements; choosing an edge-sized model does not establish edge residency or performance. A persistent Modal volume caches downloaded model weights. Runtime images are isolated; no model response or image is persisted by this application. GPU containers scale down after 600 seconds idle, with at most one container per service.

`POST /api/lab/warmup {}` starts private GPU initialization asynchronously and returns HTTP 202 with `status:"warming"`. Poll `GET /api/lab/architecture`; component `readiness` is `not_started`, `warming`, `ready`, or `error`, alongside `ready` and the independent provider-response `status`. Gemma readiness verifies a loaded model server; cuOpt readiness executes a real small GPU solve. Argon readiness means credentials are configured; `status:"verified_response"` separately records an actual validated API response. `pipelineReady` requires ready Gemma and cuOpt services; optional Argon credentials are not a prerequisite. It does not establish perception accuracy. Readiness expires after four minutes without verification or successful use; another warmup safely rechecks it. Camera inference waits for readiness rather than holding an HTTP request through model download. Startup is bounded to 840 seconds and inference to 25 seconds.

The integrated gateway defaults `/plan` to `requireFullStack:true`. This requires a bounded Gemma packet and successful native cuOpt solve before the local policy proposal is returned. Production always requires the full stack and exposes no partial-mode bypass. A configured solver failure stops the plan. The local API retains a false default for legacy contract compatibility only; that is not a supported production mission path. The legacy Gemini endpoint is separate and is not hosted by the integrated Modal gateway.

`scripts/cuopt_route_adapter.py` converts each declared corridor into a bidirectional weighted waypoint graph, computes a GPU cost matrix with `WaypointMatrix`, and calls `routing.Solve`. It accepts only `SUCCESS`, zero infeasible orders, one vehicle, both required endpoints and a finite nonnegative objective. A timeout, partial route or malformed result is an error. It compares the actual solved objective across declared corridors. This is **weighted corridor evaluation**, not free-space path generation or hydrodynamic optimal control. Each directed edge costs estimated transit seconds at a nominal 0.6 m/s plus projected current, clamped to 0.15–2 m/s, plus a proximity penalty of 30 weighted seconds per metre inside a 1.2 m contact radius. At most 32 supplied fusion contacts contribute. These explicit engineering weights are uncalibrated; `costModel`, `inputContacts` and `inputCurrentVector` accompany the result. Dynamic collision avoidance, terrain clearance and feasibility remain local checks. The cost can favor a longer clearance corridor when synthetic contacts obstruct the direct corridor.

Custom optimizer request: `{id, alternatives:[{id,points}], fusion, currentVector}`. Successful response contains matching `id`/`requestId`, `source:"cuopt"`, `configured:true`, `status:"solved"`, `solverStatus:"SUCCESS"`, `routeMode`, `objectiveCost`, `costs`, `solveTimeMs`, `model` and `solverVersion`. The local planner preserves the solver-selected route, and the engine checks request matching, freshness and local clearance. Native NVIDIA HTTP APIs have different schemas; external `CUOPT_ADAPTER_URL` must refer to this adapter. The standalone adapter requires `CUOPT_API_KEY` and binds loopback port 8091.

## Read-only team mission evidence

The lab can display the canonical team's Mission Control output without importing its control loop. Start `python3 scripts/run_lab.py --team-run-dir /absolute/path/to/run`, or set server-only `TEAM_RUN_DIR`. The bridge reads only fixed files in that directory: `registry.json`, `decisions.jsonl`, and `frame.png` (or `frame.jpg`/`frame.jpeg`). No demo directory or sample frame is selected by default. The actual unchanged `dashboard.server.read_registry` and `read_decisions` functions parse bounded in-memory snapshots; the bridge never writes these files or sends robot commands.

`GET /api/lab/team-state` returns the canonical `mode`, `registry`, `detections`, `decisions`, update timestamps and `frame_synthetic`, plus `configured`, `status`, `stale`, `provenance` and a same-origin `frameUrl`. `GET /api/lab/team-frame?v=<mtime>` serves the bounded actual PNG/JPEG. The only query parameter allowed is a numeric frame version; clients cannot choose source paths. Symlink escapes, oversized files, malformed JSON, nonfinite records and changing reads are rejected. Registry/decision sources are limited to 2 MiB each, frames to 2 MiB, state JSON to 1 MiB, returned registry entries to 1,000, detections to 256 and latest decisions to 200, with original counts reported.

Optional `source.json` contains `{"frameSynthetic":true}` for a rendered/mock frame, or false for an operator-declared camera source. Missing metadata remains **unknown**, not silently real or synthetic; `frameOriginVerified:false` explicitly distinguishes declarations from verification. The bridge does not infer provenance from coral appearance. A source older than 30 seconds is labelled stale. A missing or corrupt frame leaves registry and decisions available with `frameUrl:null` and an explicit `frameWarning`; no replacement frame is generated. On a read error, HTTP 503 preserves the last good payload with `ok:false`, `status:"error"` and a sanitized message; the UI retains its last good view. No configured directory produces explicit unconfigured state with empty arrays and no frame.

The Modal gateway includes these authenticated read endpoints and canonical parser. Without a configured directory or a received live snapshot, it reports unconfigured. The optional live relay takes precedence once a valid snapshot arrives. `scripts/push_isaac_feed.py --source http://127.0.0.1:<tunnel-port> --gateway https://<gateway>` reads the actual Isaac `/api/state` and `/api/frame.png` APIs through an operator-established loopback SSH tunnel. Supply `LAB_GATEWAY_TOKEN` through the environment or the script's hidden prompt; never put it in a URL. The script posts to the authenticated gateway-only `/api/lab/team-snapshot` endpoint, which the public Site does not expose for uploads.

The relay accepts bounded snapshots claiming `mode:"isaac"` and renderer `isaac_rtx`, a PNG up to 2 MiB, finite camera/simulation times and a recent capture timestamp. It retains only the latest frame/state in volatile memory, reports the image hash and frame lag, and labels age or camera lag above five seconds stale. These checks establish transport/provenance consistency, not cryptographic proof of the originating renderer. Live registry entries are analytical simulated observations, not Gemma detections; detections remain empty rather than inventing boxes. Source events are labelled `isaac_analytical_controller`. A rendered Isaac frame remains synthetic imagery.

The browser mission does not issue Isaac robot commands, update the Isaac world, or use this read-only stream to substitute for its own tool-camera gate. Conversely, an Isaac episode is not evidence that the independent browser model-guided mission succeeded. Deploying changes may restart GPU containers; coordinate deployments around active inference.

## Verification and remaining deployment work

Actual Modal startup loaded Gemma4 E4B on an NVIDIA A10 and executed a native cuOpt warmup solve. Earlier health-oriented camera requests returned unknown/zero despite useful visual descriptions. An earlier live uncertainty episode completed three retries and a safe abort using the **superseded Argon mission-planning architecture**; it is historical evidence, not validation of the current local-planner pipeline.

The new exact eight-field visual schema was tested against actual Gemma on an existing Isaac worker-camera image: it returned complete JSON identifying a pigmented coral colony at score 0.90 in 3,189 ms. A live broad scout-camera frame returned an ambiguous fragment classification at score 0.90 in 2,694 ms, with `gripperState:"unknown"`; this is **not accepted evidence of correct loose-fragment detection**. The constrained compact decoder produced complete replies, while viability remained explicitly unknown. These probes establish working inference/decoding, not calibrated classification or a completed live restoration mission.

The updated backend passed 38 contract/HTTP tests, including projection validation and bounded assistance. A cross-language test ran the actual Python local policy and browser engine through four loose-fragment placements and same-fragment drop recovery with **explicitly mocked model and solver transports**, asserting that the `/plan` path made no Argon call. This fixture did not exercise live `/assist` advice. This verifies integration logic, not live-model success. A separately saved actual-model episode exported at 13:41 UTC on 8 November completed one mechanical placement in 80.55 simulated seconds after Gemma uncertainty, Argon RESCAN, fresh camera evidence, cuOpt planning and a camera-dropout hold/resume. See [the completed-placement trace](evidence/live_stack_completed_placement.json). That run had zero drops and zero recoveries. Remaining live acceptance includes current-induced same-fragment recovery, repeated positive/negative camera trials and link-loss behavior; preserve failure outcomes alongside successes.
